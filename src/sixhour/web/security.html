What happens to your logs.

A business in the middle of a breach is being asked to hand its logs to a website. This page says exactly where they go, so you can decide before you paste.

The path of a log line

StepWhereWhat happens
1Your browserThe logs travel to SixHour over HTTPS. Nothing else on the page talks to any other company: no analytics, no trackers, no third-party scripts or fonts.
2SixHour server, in memoryAadhaar, PAN, phone, email and card numbers are replaced with tokens such as <EMAIL_1>. IP addresses and hostnames stay, because they are the evidence.
3SixHour server, in memoryThe rules engine analyses the masked lines. This always runs and uses no AI.
4Google Gemini API, only if AI is onThe masked lines, the organisation name and the sector are sent to Gemini to write the incident record. Untick "Use Gemini" on the desk and this step is skipped.
5Back to your browserThe record, clocks and drafts are returned. The server keeps nothing: there is no database and no file is written.

Plain warning about the public desk. When AI is on, masked lines are processed by Google under the Gemini API terms. Masking removes the identifiers listed above, not every sensitive detail a log can hold. If your logs must not leave your control, untick "Use Gemini", or talk to us about a pilot deployment.

What SixHour keeps

  • On our servers: nothing you paste. Request logs record the time, the path, the response code, how long it took and a request ID. They never record log contents, organisation details or drafts.
  • In your browser: the open incident (masked lines, record, drafts and the details you typed) is saved in this browser's local storage so the clocks survive a reload. "Close incident" on the desk deletes it. It is never sent anywhere.
  • Cookies: none.

Translation

Translating the notice to affected people sends that notice text to Gemini. The notice contains your organisation's name and the contact details you typed, so customers can reach you.

How the service is built

  • A strict Content-Security-Policy: the pages can load code only from SixHour itself.
  • Everything from the logs and the model is written to the page as text, never as HTML.
  • Rate limits on the analysis and translation endpoints, and a hard size limit on what can be sent.
  • Guardrails between the model and you: evidence that cites a line not in your logs is dropped, and the model cannot remove a personal-data finding the rules engine proved.
  • The source is open under the MIT licence. Read it, or run it yourself, on GitHub.

Where it runs

The public desk currently runs on Vercel. Pilot deployments are planned for Google Cloud Run in Mumbai (asia-south1), so that processing stays in India, which matters for the CERT-In direction on keeping logs within Indian jurisdiction.

What SixHour is not

It is not a certified security product, and it holds no ISO 27001 or SOC 2 certificate today. It is an early product built in the open. If a certificate is a condition for you, we would rather say so now.

Found a problem?

Report a vulnerability privately through GitHub security advisories. Please do not open a public issue for a security bug.
